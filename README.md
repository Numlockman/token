# 文化祭用 人力マイニング v1.1

HTML / CSS / JavaScript + Electron のローカルアプリです。送金、採掘、手数料、ID検索、課題印刷、JSONL保存・再起動復旧を実装しています。

**このZIPはソースコードです。Windowsの完成済みexeは含まれていません。** この開発環境では依存パッケージの取得が制限されているため、Electronの起動・Windows向けパッケージ化・実画面確認は未実施です。台帳ロジックはNode.jsで14項目の自動テストに合格しています。

## 初回準備：インターネットにつながるWindows PC

1. Node.js 24系をインストールする。
2. ZIPを展開する。
3. `package.json` があるフォルダーでターミナルを開く。
4. 次を順番に実行する。

```powershell
npm install
npm test
npm start
```

`index.html` のダブルクリックでは台帳保存機能は動きません。Electronから起動してください。

初回 `npm install` で生成される `package-lock.json` を保管してください。以後同じ依存構成を再現するときは `npm ci` を使います。

## 文化祭用exeを作る

同じフォルダーで、ネット接続した状態で実行します。

```powershell
npm run dist:win
```

成功すると `dist` に `HumanMining` のportable exeができます。exeを学校のWindows PCへコピーして起動します。ビルドにはネット接続が必要ですが、生成したアプリの実行にはネット接続、Node.js、外部サーバーは不要です。対象はWindows x64です。学校PCでの起動確認は事前に行ってください。

## v1.1の変更

- 掛け算は最大3桁×2桁を1回。4桁の2乗を廃止。
- 目標成功率は初期1/3、設定で1/4に変更可能。
- 課題のNonce全10000通りから、目標成功率に最も近くなる整数ターゲットを自動選択。
- 実際の成功率とターゲットを画面・印刷課題に表示。正解Nonceは表示しません。
- 新規ブロックはversion 2。旧version 1ブロックは元の式で検証して残高を引き継ぎます。旧台帳の書き換えは不要です。

## 最初の体験

1. 「採掘のみ」を選び、採掘者ID（例 `03020017`）を入力して課題を発行。
2. 30桁を紙に写すか「課題を印刷」。末尾の `????` をNonceで置き換える。
3. 画面の式でHashを計算。判定上限より小さい答えを探す。
4. NonceとHashをそれぞれ4桁で入力し「採掘結果を確認・確定」。
5. 初期設定では採掘者に1.0 Coinが発行される。
6. コインがあるIDを送信元にして「送金を確定する」を選ぶ。
7. 採掘成功時に送金され、採掘者に報酬と0.2 Coinの手数料が入る。

金額は小数1桁まで。IDの先頭の0も保持します。`00000000` はシステム予約です。本人確認はスタッフが行います。

## 保存と復旧

- 正式な台帳は `blockchain.jsonl` だけです。保存先は画面に表示され、「保存フォルダーを開く」で確認できます。
- Windowsでは通常 `%APPDATA%\human-mining\data\blockchain.jsonl`。exeと同じ場所には保存しません。同じWindowsユーザー・同じアプリ名で再起動してください。
- バックアップボタンで台帳を別ファイルにコピーできます。PCを移す場合はexeだけでなく台帳も移してください。
- 既存の残高を復元するときはアプリを終了し、現在の台帳を別途バックアップしたうえで、バックアップを保存先の `blockchain.jsonl` に配置して再起動します。
- 各ブロックを検証後に追記し、`fsync` 完了後に残高と画面を更新します。
- 最後の改行をコミット境界とします。未完了の末尾は原本全体を `.bak` に退避してから切り落とし、完成している行まで復元します。
- 完成した行に不正がある場合は、読み飛ばさず原本を保持して起動を停止します。
- 保存エラー後はそのセッションの追記を止めます。書き込みが実際には完了している場合もあるため、再起動後に最新ブロックと残高を確認してください。
- `fsync` は突然の終了に備える処理ですが、PCやディスク自体の故障まで保証するものではありません。

## この版の運用

- 採掘課題は同時に1件。1件を確定または取消してから次を発行します。
- 採掘者は課題発行時に指定します。この版は複数採掘者の競争・取引待ち行列を実装していません。
- 未確定の課題はメモリーのみで保持し、終了・再起動で破棄します。未確定の送金で残高は引き落としません。
- 設定は課題中に変更できません。適用した目標成功率・報酬と、自動決定したターゲットは次の確定ブロックに記録され、再起動時は最後の確定ブロックの設定に戻ります。未採掘の設定変更は保存されません。
- 初登場IDは自動登録します。確定ブロックに登場するIDは再起動で復元します。検索・課題発行だけのIDは再起動時に忘れますが、再入力すれば残高0で再登録されます。
- 台帳の金額は **0.1 Coinを1とする整数**。例: `amount:20` は2.0 Coin、`fee:2` は0.2 Coinです。画面ではCoin単位で表示します。
- 通貨名は仮に「人力マイニング」。まだ特定の名称・人物名は入れていません。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `src/core.cjs` | 金額、ID、ハッシュ、検証、残高更新 |
| `src/ledger.cjs` | JSONL、復旧、採掘課題、二重確定防止 |
| `src/main.cjs` | Electron起動・保存操作・二重起動防止 |
| `src/preload.cjs` | 画面から許可した操作だけを渡す橋渡し |
| `src/index.html` / `style.css` / `renderer.js` | 操作画面・課題印刷 |
| `test/ledger.test.cjs` | 残高・破損・保存失敗などの自動テスト |
| `DESIGN.md` | 未確定事項の決定・計算方法・データ形式 |
