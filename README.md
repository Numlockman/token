# 文化祭用 人力マイニング v1.2

HTML / CSS / JavaScript + Electron のオフラインアプリです。送金依頼の付箋ボード、最大3人の早い者勝ち採掘、手数料、ID検索、JSONL保存・復旧を実装しています。

## 今回の変更

- 採掘のみ・送金ありの両方を、指定順序の35桁に統一。
- 掛け算は最大3桁×2桁を1回。35桁の全7組を使う新しい式に変更。
- 右の掲示板に送金依頼を付箋として掲示。クリックすると左の問題発行に入ります。
- 同じ依頼・前Hash・報酬・目標成功率で、採掘者IDを変えて最大3人まで同時に発行。
- 最初の正解が保存されたら1回だけ送金・報酬を確定し、他の問題は失効。
- 既存の30桁台帳は元の式で検証し、残高を引き継ぎます。

**ソースコードの提供です。完成済みexeは含みません。** この開発環境ではElectronの実画面・Windows実機の動作確認は未実施です。Node.jsで22項目のロジックテストに合格しています。

## Windowsでの初回準備

インターネットにつながるWindows x64 PCでNode.js 24系をインストールします。GitHubのCode → Download ZIPでソースを取得して「すべて展開」し、`package.json` があるフォルダーを開きます。

ファイルは開かず、エクスプローラーでAlt+D → `powershell` → Enter。次を1行ずつ実行してください。

```powershell
npm.cmd install
npm.cmd test
npm.cmd start
```

初回の取得中は表示が止まる場合があります。処理が終わって `PS C:\…>` に戻るまで待ってください。`index.html` を直接開く方式ではありません。

既に旧版を動かしている場合はアプリを終了し、台帳をバックアップしてから新しいソースで上のコマンドを実行します。同じWindowsユーザー・同じアプリ名で起動すれば保存先は変わりません。台帳を初期化する必要はありません。更新すると未確定の問題・依頼は破棄されるので、ラウンドを終えてから更新してください。

初回 `npm install` で生成される `package-lock.json` を保管してください。同じ依存構成を再現するときは `npm.cmd ci` を使えます。

## 文化祭用exeを作る

ネット接続した状態で同じフォルダーから実行します。

```powershell
npm.cmd run dist:win
```

成功すると `dist` にHumanMiningのportable exeができます。学校PCへコピーして起動します。生成後の実行にネット接続・Node.js・外部サーバーは不要です。学校PCでの事前の起動確認は必要です。

## 使い方：採掘のみ

1. 左の「採掘のみを選ぶ」を押す。
2. 採掘者IDを入力し「問題を発行」。
3. 2人目・3人目は採掘者IDだけ変えて「同じ条件で参加者を追加」。
4. 下に並ぶ各人の問題を画面で確認し、必要なら数字を紙に写す。
5. 参加者がNonceを変えて手計算する。NonceとHashは必ず4桁で入力。
6. 最初の正解が保存された採掘者に報酬を発行。他の用紙は無効になる。

最初はコインがないので、採掘のみでコインを発行してください。初期報酬は1.0 Coinです。

## 使い方：付箋から送金

1. 左の「送金依頼を掲示する」を開く。
2. 送信者ID・送信先ID・送金額を入力し「付箋を掲示」。
3. 右の掲示板の付箋をクリックすると、左の発行内容に反映される。
4. 採掘者IDを入力して発行。2人目・3人目は同じ条件で追加。
5. 先着の正解が保存されると送金され、採掘者へ報酬＋0.2 Coinの手数料が入る。
6. 確定した付箋は掲示板から消える。他の送金依頼は残る。

送金額は **0.1〜99.9 Coin**。内部の3桁は0.1 Coin単位で、`001`=0.1 Coin、`999`=99.9 Coinです。手数料0.2 Coinは送金額とは別に送信者が負担します。

掲示だけでは残高を予約・引き落としません。別の送金が先に確定して残高が足りなくなった付箋は「残高不足・選択不可」になります。

## 競争のルール

- 同時に進められるラウンドは1つ。問題は最大3人分。
- 同じ採掘者IDは同じラウンドに重複参加できません。
- ラウンド中は別の依頼・採掘のみへの切替・運営設定の変更はできません。
- 計算用35桁の固定部分は採掘者IDだけが違います。Nonceは各参加者が探します。
- 各採掘者のハッシュ分布から、同じ目標成功率（1/3または1/4）に合わせてターゲットを個別に決めます。ターゲットの数字は参加者によって異なる場合があります。
- 「先着」はPCが最初に正解として検証し、保存を完了した回答です。スタッフが1台のPCに入力する運用です。
- 間違った回答ではラウンドは終了しません。正解確定後は、他の人の正しい回答でも無効です。
- 取消はラウンド全体に対して行います。全用紙を失効させ、依頼は掲示板に残します。再発行した場合も古い用紙は無効です。

## 計算式

35桁を5桁ずつA〜Gに区切り、各組の「上2桁＋下3桁」をa〜gとします。例: `12345`→12+345=357。

```text
X = (a + c + e + g) の下3桁
Y = (b + d + f + g) を90で割った余り + 10
Hash = X × Y の下4桁
```

最大3桁×2桁の掛け算1回。Hashは4桁で、ターゲット未満なら成功です。目標成功率は初期1/3、設定で1/4に変更できます。詳しくは `DESIGN.md`。

## 保存・復旧

- 正式な台帳は `blockchain.jsonl`。画面の「保存フォルダーを開く」で確認できます。
- Windowsでは通常 `%APPDATA%\human-mining\data\blockchain.jsonl`。exeと同じ場所ではありません。
- PCを移す場合はexeだけでなく台帳も移してください。アプリ終了後、移行先の保存フォルダーに同名で配置して再起動します。既存台帳がある場合は先にバックアップしてください。
- ブロックを検証→追記→fsync→残高更新の順。再起動で全ブロックを検証して残高を再構築します。
- 未完了の末尾は原本を `.bak` に退避してから切り落とし、完成している行まで復元します。
- 完成済みの行が不正な場合は読み飛ばさず、原本を保持して起動を停止します。
- 保存失敗後は追記を停止します。完全な行がディスクに残っている場合もあるので、再起動して最新ブロックを確認してください。
- **未確定の付箋・問題はメモリーのみで、アプリ終了・再起動時に破棄されます。** バックアップ対象も確定済み台帳のみです。
- 設定変更は次の確定ブロックに保存されます。未採掘の設定変更は再起動すると失われます。
- 確定ブロックに登場したIDは復元します。検索や未確定依頼にだけ登場したIDは再入力時に0残高で再登録します。

本人確認はスタッフが行う展示用通貨です。暗号学的安全性や分散合意は実装していません。
